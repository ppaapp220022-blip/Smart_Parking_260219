# Smart Parking System

실시간 주차 현황 조회, 입출차 관리, 요금 정산, 월정액 회원 관리, 관리자 보안 인증, 매출 통계까지 한 번에 다루는 **관리자용 스마트 주차 운영 시스템**입니다.  
5인 협업으로 진행한 Java Servlet/JSP 기반 프로젝트이며, 단순 CRUD를 넘어 **운영 정책 반영, 보안 흐름 설계, 정산 로직 구현, 데이터 시각화, 협업 병합 경험**까지 담은 팀 포트폴리오입니다.

## 1. Project Summary

- **목표**: 중소형 주차장의 현장 운영 업무를 웹 기반으로 디지털화
- **핵심 사용자**: 주차장 관리자
- **주요 문제 정의**
  - 빈 주차면과 사용 중인 주차면을 한 화면에서 확인하기 어렵다.
  - 회원/비회원 차량을 구분해 입출차와 정산을 처리하기 번거롭다.
  - 요금 정책 변경과 할인 규칙 반영이 수작업에 의존한다.
  - 매출 현황을 일별/월별/차종별로 분석하기 어렵다.
- **해결 방식**
  - 20개 주차면을 시각화한 대시보드
  - 회원 자동 인식 기반 입차 처리
  - 회차 시간, 추가 요금, 일일 최대 요금, 차종 할인, 월정액 무료를 반영한 정산 로직
  - 관리자 권한 분기와 이메일 OTP 기반 2차 인증
  - Chart.js 기반 매출 통계 시각화

## 2. Key Features

### 2-1. 실시간 대시보드

- A1 ~ A20 주차면 상태를 한 화면에서 확인
- 빈 자리 / 사용 중 상태를 직관적으로 구분
- 사용 중인 차량의 차량번호와 상태를 기반으로 출차 화면 이동
- 주차면 클릭 기반 입차/출차 흐름 연결

### 2-2. 차량 입차 관리

- 차량번호와 주차면 유효성 검증
- 이미 사용 중인 주차면 선택 차단
- 동일 차량의 중복 입차 방지
- 월정액 회원 차량일 경우 회원 정보와 연계하여 입차 처리

- 회차 시간 무료 처리

- 경차 / 장애인 / 월정액 할인 반영
- 카드 / 현금 / 월정액 결제 방식 구분

### 2-4. 월정액 회원 관리

- 구독 만료 상태 자동 반영

### 2-5. 관리자 계정 및 보안

- 관리자 계정 생성 및 권한 분기

- BCrypt 기반 비밀번호 해시 처리
- 이메일 인증 및 OTP 기반 2차 인증
- 세션 검증 필터와 캐시 제어를 통한 뒤로가기 보안 강화
- 비밀번호 찾기용 OTP 및 임시 비밀번호 발급 흐름 제공

### 2-6. 요금 정책 관리

- 회차 시간, 기본 요금, 추가 요금, 할인율, 일일 최대 요금 관리
- 활성 정책 기반 정산 반영
- 잘못된 할인율 값에 대한 방어 로직 포함

### 2-7. 매출 통계

- 일별 시간대 매출
- 월별 일자별 매출
- 차종별 비율
- Chart.js 기반 시각화

## 5. Architecture

이 프로젝트는 전형적인 **MVC 패턴 기반의 Servlet/JSP 구조**로 설계되었습니다.

- **Controller**
  - 요청 수신, 파라미터 검증, 화면 이동 및 서비스 호출
- **Service**
  - 요금 계산, 인증 흐름, 구독 만료 처리 등 비즈니스 로직 담당
- **DAO**
  - JDBC 기반 데이터 접근
- **DTO / VO**
  - 계층 간 데이터 전달과 DB 매핑 분리
- **Filter**
  - 로그인 세션 검증 및 캐시 제어

```text
src/main/java/org/example/smart_parking_260219
├─ connection   # DB 연결(HikariCP)
├─ controller   # 로그인/회원/정책/입출차/통계/결제
├─ dao          # JDBC 기반 데이터 접근
├─ dto          # View 전달용 DTO
├─ filter       # 로그인 체크 필터
├─ mail         # 이메일 발송 설정 및 서비스
├─ service      # 비즈니스 로직
├─ util         # 패스워드/매퍼 유틸
└─ vo           # DB 매핑용 VO
```

## 6. Database Design

주요 테이블은 아래와 같습니다.

- `member`: 월정액 회원 및 차량 정보
- `manager`: 관리자 계정, 권한, 이메일
- `validation`: OTP 및 인증 만료 시간 관리
- `parking_spot`: 주차면 상태
- `parking`: 입출차 기록
- `fee_policy`: 요금 정책
- `payment`: 결제 내역

초기 스키마와 더미 데이터는 `src/main/resources/sql/init.sql` 에 정의되어 있으며, 실제 저장소에서는 `member`, `parking`, `payment`, `fee_policy`를 중심으로 도메인 흐름이 연결됩니다.

- 회원 목록 10건 단위 페이징

- 출차 차량 조회와 정산 흐름을 페이지 전환으로 자연스럽게 연결

### 8-4. 데이터 시각화

## 11. Retrospective

### 강수현

처음으로 팀 프로젝트와 조장 역할을 함께 맡으며, 개발 자체보다도 **의사결정과 협업 조율이 프로젝트 완성도에 큰 영향을 준다**는 점을 깊이 체감했습니다. 정산과 통계 기능 구현 과정에서는 여러 테이블을 동시에 다루는 SQL과 데이터 가공이 핵심이었고, 이를 반복적으로 해결하면서 쿼리 설계와 데이터 처리 역량을 크게 끌어올릴 수 있었습니다. 또한 Git 병합 충돌과 버전 관리 이슈를 겪으며 협업 환경에서의 형상 관리 중요성을 실무적으로 배웠습니다.

### 김민기

회원 관리 기능을 담당하며 요구사항과 실제 구현 사이의 차이를 조정하는 경험을 했습니다. 초기에 회원과 월정액 개념을 분리해 설계했다가, 프로젝트 요구사항에 맞게 다시 구조를 재정비하면서 **기획 이해와 데이터 모델 정합성의 중요성**을 배웠습니다. 회원 목록, 등록, 수정 기능을 다시 맞춰가는 과정은 쉽지 않았지만, 그만큼 설계 변경에 대응하는 능력과 새로운 기술을 찾아 학습하는 태도를 키울 수 있었습니다.

### 서민성

요금 정책 기능을 구현하면서 팀원의 피드백을 통해 예외 상황과 개선 포인트를 더 많이 발견할 수 있었습니다. 혼자였다면 지나쳤을 부분을 협업 과정에서 보완할 수 있었고, 이를 통해 **소통이 품질을 높이는 핵심 수단**임을 체감했습니다. 이번 프로젝트는 기능 구현 자체뿐 아니라, 다음 협업에서는 더 적극적으로 의견을 공유하고 논의해야겠다는 방향성을 남긴 경험이었습니다.

### 서주연

로그인, 인증, 보안 로직을 맡아 **권한별 2차 인증 흐름, BCrypt 기반 비밀번호 해시, 세션/캐시 보안 처리**를 설계했습니다. 구현 과정에서 이중 해싱 문제, 로그아웃 후 뒤로가기 보안 취약점, 권한별 메뉴 분기 오류를 직접 해결하며 보안이 단순한 부가 기능이 아니라 전체 MVC 흐름과 맞물린 구조적 설계 과제임을 배웠습니다. 또한 기능 변경 과정에서 DB 구조까지 함께 점검하게 되며 초기 설계 품질의 중요성도 크게 느꼈습니다.

### 한정수

입출차 기능을 담당하며 막연했던 요구사항을 스토리보드 중심으로 구체화해 나갔고, 구현이 쌓일수록 시스템 흐름이 하나의 서비스처럼 연결되는 경험을 했습니다. 기능 확장과 병합 과정에서는 예상치 못한 오류가 많았지만, 기존 코드와 팀원의 코드를 비교 분석하며 해결해 나가면서 **문제 해결력과 통합 관점의 사고 방식**을 키울 수 있었습니다. 특히 협업 코드가 하나로 묶여 실제 동작하는 순간 큰 성취감을 느꼈고, 더 큰 팀에 기여하는 개발자로 성장하고자 하는 동기를 얻었습니다.

## 12. Lessons Learned

- 요구사항 정의가 바뀌면 가장 먼저 영향받는 것은 UI가 아니라 **데이터 모델과 도메인 규칙**이라는 점
- 보안 기능은 화면 단위가 아니라 **세션, 컨트롤러, 서비스, DB 흐름 전체**를 함께 봐야 한다는 점
- 통계 기능은 차트 라이브러리보다 **데이터 집계와 전처리 설계**가 더 중요하다는 점
- 협업에서는 구현 속도보다 **브랜치 전략, 병합 규칙, 역할 간 커뮤니케이션**이 품질을 좌우한다는 점
